# 参与人员抽屉技术实施方案

> 用途：直接交给 5.6 Terra 执行。
> 基线日期：2026-09-03。
> 原型：`prototype/龙城小程序.pen`。
> 当前分支：`feat/board-game-library-20260831`。
> 本方案阶段只定义实施，不代表允许部署、合并或覆盖现有未提交修改。

## 1. 目标

将活动详情页现有“参与人”旧抽屉替换为最新原型中的“参与人员”抽屉，完成：

1. 最新抽屉结构、签到进度、人员表格、空状态的数值还原。
2. 管理员左滑“取签 / 补卡 / 删除”。
3. 普通用户可查看所有成员的签到时间和签到位置，但不显示列表管理操作。
4. 用户定位签到成功后，由后端调用高德逆地址解析并持久化简要地点和详细地址。
5. 保留现有报名、签到、管理员补卡、管理员取消签到、删除参与人接口能力，并消除旧文案和旧记账残留。

## 2. 实施边界

### 2.1 本次包含

- 活动详情页参与人员抽屉。
- 必要的独立前端组件、图标资源和数据适配。
- 签到地址字段、数据库迁移、高德逆地址解析服务。
- 相关前后端自动化测试和 L1 验收。

### 2.2 本次不包含

- 不调整活动详情页抽屉之外的视觉模块。
- 不改变普通用户当前通过详情页主按钮取消自己报名的路径。
- 不给普通用户开放补卡、取签、删除等管理能力。
- 不实现拖拽条下拉关闭；拖拽条仅为视觉装饰。
- 不在小程序端请求高德，也不把高德 Key 放进前端仓库。
- 不部署后端、不合并分支、不提交 Git，除非执行时用户另行明确要求。

## 4. 已确认业务规则

### 4.1 查看权限

- 管理员和普通用户都能看到全部报名成员。
- 管理员和普通用户都能看到所有成员的签到时间和签到位置。
- 不因角色裁剪上述签到信息字段。

### 4.2 人数和进度

- 有人数上限：显示 `18 / 24 人`。
  - 18 = 当前报名人数。
  - 24 = 活动人数上限。
- 无人数上限：只显示 `18 人`。
- 进度条分子 = 已签到人数。
- 进度条分母 = 当前报名人数，而不是人数上限。
- 当前报名人数为 0 时，进度为 0，不允许除零或出现 `NaN`。
- 未签到人数：`max(报名人数 - 已签到人数, 0)`。

### 4.3 管理操作矩阵

| 用户角色 | 人员已签到 | 人员未签到且活动已结束 | 人员未签到且活动未结束 |
|---|---|---|---|
| 管理员 | 取签 + 删除 | 补卡 + 删除 | 删除 |
| 普通用户 | 无左滑操作 | 无左滑操作 | 无左滑操作 |

说明：

- “取签”业务含义为管理员取消签到，沿用现有 `DELETE admin-checkin` 接口。
- “补卡”沿用现有 `POST admin-checkin` 接口。
- 前端用户文案全部使用“取签”“补卡”，不再显示“取消签到”“补签”。
- 普通用户取消自己的报名继续走活动详情页主按钮，不从人员列表暴露删除能力。

### 4.4 签到地址

- 定位签到：记录签到经纬度、简要地点、详细地址。
- 管理员补卡：无真实签到定位，地址和经纬度均为空。
- 管理员取签：清空签到时间、方式、经纬度、简要地点、详细地址。
- 高德逆地址解析失败不能阻塞签到；签到成功、地址留空，抽屉显示 `—`。

### 7.1 组件结构

新增独立组件，避免继续把抽屉复杂状态堆在活动详情页：

```text
miniprogram/components/participants-drawer/

  index.wxml
  index.wxss
  index.js
```

建议组件属性：

```js
properties: {
  visible: Boolean,
  participants: Array,
  participantCount: Number,
  checkinCount: Number,
  maxParticipants: null | Number,
  activityStatus: String,
  isAdmin: Boolean,
  safeBottomRpx: Number

```

建议组件事件：

```text
close
retrocheckin   // 补卡，detail: { participantId, name }
cancelcheckin  // 取签，detail: { participantId, name }
remove         // 删除，detail: { participantId, name }
```

活动详情页继续负责：接口调用、确认弹窗、刷新活动详情、错误 Toast；组件只负责展示和手势状态。

### 7.2 数据适配

不要全局修改现有活动日期时间格式函数，避免影响其他页面。给参与人员单独增加格式化逻辑：

```js
{
  rowKey,
  id,
  userId,
  name,
  avatarUrl,
  checkedInAtRaw,
  checkinDateText,      // MM月DD日
  checkinTimeText,      // HH:mm:ss
  checkinLocationText,  // locationName || address || "—"
  hasCheckedIn,
  availableActions
}
```

要求：

- 保留原始 ISO 时间，通过明确的日期解析转换本地时区，不能直接字符串切片。
- 列表继续沿用当前“报名时间倒序、最近报名在前”的稳定顺序。
- `rowKey` 必须使用参与记录 id，不用数组下标作为正常数据主键。
- 地址优先级：`checkinLocationName || checkinAddress || "—"`。

### 7.3 左滑状态机

组件内部只允许一行展开，建议状态：

```js
data: {
  openRowKey: "",
  draggingRowKey: "",
  dragOffsetRpx: 0,
  directionLocked: "" // "horizontal" | "vertical" | ""
}
```

手势流程：

1. `touchstart`：记录起点、时间、当前展开位移。
2. `touchmove`：
   - 先比较横纵位移，横向明显大于纵向才锁定横滑。
   - 锁定纵向后不拦截 `scroll-view`。
   - 横向位移限制在 `[−actionWidth, 0]`。
3. `touchend/cancel`：按距离和速度吸附到 0 或完整动作宽。
4. 点击其他行、遮罩、关闭抽屉、执行动作成功或刷新数据后关闭展开行。
5. 一按钮行的 `actionWidth` 为 80px 对应 rpx；两按钮行为 168px 对应 rpx，不能固定假设所有行都是两按钮。

性能要求：

- 不在每一帧 `setData` 整个人员数组。
- 优先采用组件局部状态或 WXS 只变更当前行 transform；最终吸附结果再同步到组件 Data。
- `transform: translate3d(...)` 负责移动，避免逐帧修改 `left`。
- 长列表滚动过程中不得误触横滑，横滑过程中不得带动纵向滚动。

### 7.4 确认文案

- 补卡：标题“确认补卡”，成功“补卡成功”，失败“补卡失败”。
- 取签：标题“确认取签”，成功“已取签”，失败“取签失败”。
- 删除：只说明将该成员从活动中删除，不得出现“账单”“记账明细”等旧业务文案。

所有操作成功后：

1. 关闭当前滑开行。
2. 重新拉取活动详情。
3. 由刷新后的服务器数据重算人数、签到数、进度和动作状态。

### 8.4 高德服务

新增：

```text
backend/app/services/amap_service.py
```

建议接口：

```python
@dataclass
class ReverseGeocodeResult:
    location_name: str | None
    address: str | None


def reverse_geocode(*, lat: float, lng: float) -> ReverseGeocodeResult | None:
    ...
```

请求：

```text
GET https://restapi.amap.com/v3/geocode/regeo
key={AMAP_WEB_SERVICE_KEY}
location={lng},{lat}
extensions=all
radius=1000
```

处理要求：

- 使用项目已有 `httpx`。
- 设置连接/总超时，不无限等待。
- 检查 HTTP 状态和高德业务状态。
- `formatted_address` 存入 `checkin_address`。
- 简要地点不能固定优先 POI：合并可用 POI 与 AOI，按返回的 `distance` 取最近名称；距离缺失时优先 AOI，再降级 POI，最后为空。实测现有签到坐标中 AOI 明显比首个 POI 更近。不要把空字符串写成有效地址。
- 捕获超时、网络错误、响应格式异常并记录结构化告警；不得记录 Key。
- Key 未配置时直接返回空地址结果，不影响本地测试和签到主流程。
- 官方参考：`https://lbs.amap.com/api/webservice/guide/api/georegeo`。

### 8.4.1 真实坐标验证基线

已使用线上现有签到记录中的两组经纬度完成逆地址解析验证。高德请求参数必须按 `location={经度},{纬度}` 传递：

| 签到坐标（纬度, 经度） | `formatted_address` | 最近地点候选 |
|---|---|---|
| `40.0433, 116.316` | 北京市海淀区清河街道天韵阁当代城市家园 | 当代城市家园（AOI 距离 0m） |
| `40.0674, 116.323` | 北京市昌平区回龙观街道南店北路新龙城 | 新龙城（AOI 距离约 25.8m） |

两组请求均返回 `status=1 / info=OK / infocode=10000`，证明当前 Key、接口和已有签到坐标可正常配合使用。实现时沿用以下规则：

- 详细地址取 `formatted_address`。
- 简要地点合并 POI、AOI 有效候选后，优先取 `distance` 最小的名称；不能固定使用第一个 POI。
- GPS 精度和高德数据粒度可能只解析到小区、园区等区域名称，不保证命中用户填写的具体场馆名，此情况不视为接口失败。
- 自动化测试继续 mock 高德请求；上述真实样本只作为人工联调基线，测试过程不得依赖线上活动数据。

### 8.5 签到事务顺序

在 `backend/app/services/activity_service.py` 中：

1. 先完成报名身份、签到时间窗、活动地点和签到半径校验。
2. 使用签到提交的 GCJ-02 经纬度调用高德逆地址解析。
3. 写入签到时间、方式、经纬度、简要地点、详细地址。
4. 高德失败时仍写入签到时间、方式和经纬度，地址为空。
5. 管理员补卡时将经纬度及两类地址明确置空。
6. 管理员取签时将时间、方式、经纬度及两类地址全部置空。

外部高德调用失败不得回滚本应成功的签到。实现时避免把数据库事务长时间保持在外部网络请求上：完成业务校验后请求高德，再集中写库提交。
