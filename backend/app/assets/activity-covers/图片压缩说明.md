# 活动封面图片压缩说明

记录日期：2026-09-09。当前选定方案为 JPEG Q88；下文同时保留 WebP 尝试及回滚记录。上线状态以本节为准。


## 当前方案：JPEG Q88（用户确认）

- 高清原图按 JPEG Q88 编码，保持原始宽高、原有色度采样，优化编码，不裁切、不缩放。
- 原件仍在各画师原目录；交付件存放于 `jpeg-q88-v1/`，映射及校验值记录在 `jpeg-q88-manifest.json`。
- 每张素材比较 Q88 编码、无损 JPEG 系数优化与原件复制的体积，选择最小者，避免压缩后反而变大。实际93张高清封面全部使用Q88；其余194张小素材采用无损优化或原样复制。
- Q88不是“保留88%画质”；本次是有损压缩，不承诺逐像素一致。原件和色彩配置保留。
- 93张高清封面：50,096,189 → 33,002,793字节（50.096 → 33.003 MB），减少34.1%。
- 全部287份素材：54,564,002 → 37,415,846字节（54.564 → 37.416 MB），减少31.4%。
- 构建脚本：`backend/scripts/build_cover_jpeg.py`。依赖 Python、Pillow、jpegtran。再次执行只允许相同输出；检测到发布文件内容不同时拒绝覆盖，必须新建发布版本。
- 本地交付开关：`ACTIVITY_COVER_JPEG_ENABLED=1`；默认关闭。启用后JPEG优先于旧WebP开关，URL带内容哈希，服务端原件解析仍指向原件。
- 验收：287个原件及交付件SHA256、JPEG解码、尺寸和体积核验通过；7项专用测试、323项前端测试通过。微信模拟器287/287下载及getImageInfo解码成功；首页11/11卡片显示成功；重启后15/15首页素材命中持久缓存。公网93条封面记录、287个JPEG链接均验证成功。尚未覆盖本轮iOS/安卓真机验收。
- 当前状态：2026-09-09已部署JPEG Q88。服务器原件与交付件均保留，线上接口已返回带内容版本的Q88目录链接，后端服务active。本次图片URL切换不要求前端重新发版；已有客户端需刷新活动列表获取新地址，旧地址保持有效。100MB持久缓存属于此前本地前端改动，其线上可用性仍取决于对应前端版本是否发布，不能把本次后端切换等同于缓存前端已发布。
- Q92仅为未上线的试验版本，保留文件，不作为本次交付。生产通过systemd独立配置 `30-cover-jpeg-q88.conf` 启用 `ACTIVITY_COVER_JPEG_ENABLED=1`；回滚设为0并重启服务，原件地址仍可用。

## 1. WebP历史方案：原件与压缩件放在哪里

- 各画师目录内的 `images/`：93张高清JPEG原件。
- 各画师目录内的 `thumbs/`、`glass/`、`avatar.jpg`：原有缩略图、毛玻璃衍生图和画师头像。
- `webp-q90-v1/`：独立存放WebP版本，内部保留相同的画师、图片分类和文件名结构，仅扩展名改为 `.webp`。
- `catalog.json`：原始素材目录，仍指向原件。
- `webp-q90-manifest.json`：原件与WebP的对应关系、各自SHA-256校验值和文件字节数。

示例：

```text
aleksey-rico/images/aleksey-rico-001.jpg                 原件
webp-q90-v1/aleksey-rico/images/aleksey-rico-001.webp     压缩件
```

原件不得被压缩件覆盖。以后重新编码应从JPEG原件开始，不从已压缩WebP反复转码。

## 2. 本次压缩方式

使用本机 libwebp/cwebp 1.6.0，参数与审阅样张一致：

```sh
cwebp -quiet -q 90 -m 6 -sharp_yuv 原件.jpg -o 压缩件.webp
```

- **WebP有损压缩**：降低文件体积，但不承诺与原件逐像素一致。
- **Q90**：编码质量档位，不表示保留90%的画质或缩小到原大小的90%；不同编码格式的Q值不可直接等同。
- **`-m 6`**：编码器最慢、计算更充分的压缩方式。影响制作压缩件所需时间，不是手机执行压缩算法。
- **`-sharp_yuv`**：使用更锐利的RGB到YUV颜色转换，不等于给图片额外添加锐化滤镜。
- **`-quiet`**：减少命令输出，不影响画质。
- **保持宽高**：不缩放、不裁切、不改变图片比例；毛玻璃文件从原有毛玻璃衍生图编码，不重新设计效果。

文件变小主要减少传输量；尺寸不变，不意味着解码后的内存占用同比减少。首次网络建连慢等问题也不会仅凭压缩彻底解决。

## 3. 实测体积

以下采用十进制MB，1 MB = 1,000,000字节。

| 类别 | 数量 | 原件合计 | WebP合计 |
|---|---:|---:|---:|
| 高清封面 | 93 | 50.096 MB | 26.707 MB |
| 缩略图 | 93 | 2.406 MB | 2.721 MB |
| 毛玻璃衍生图 | 93 | 2.024 MB | 1.535 MB |
| 画师头像 | 8 | 0.037 MB | 0.035 MB |
| **总计** | **287** | **54.564 MB** | **30.998 MB** |

高清封面合计减少约46.7%；全部素材合计减少约43.2%。部分小文件反而变大，尤其缩略图合计增加，不能把总体减重比例理解为每张图都减少同样比例。

## 4. 生成与校验

在项目 `backend` 目录运行：

```sh
python3 scripts/build_cover_webp.py
```

依赖 Python、Pillow 和 PATH 中可执行的 cwebp。脚本会重新生成压缩件和清单，运行前应保留已有发布版本；不要直接在生产目录盲目重跑。

本次已核验：287个原件SHA-256未变化；287个WebP校验值一致、可由Pillow解码、与各自原件宽高一致。公网287个WebP地址曾逐个验证返回200及 `image/webp`。这些检查不替代小程序端兼容性验收。

以后编码器版本、参数或原件改变，应生成新的发布目录，保留旧版本以便回滚；接口链接应带新内容版本，避免复用旧缓存。

- 如将来再选择WebP，须另行完成其准备及原生渲染兼容性验证。本次JPEG Q88不依赖该修复。
