# 首页媒体诊断验收与发布说明

## 2026-09-09：缓存摘要与投递减负（本地待前端发布）

- 每次首页摘要/异常快照附带 `imageCache`：checked、hits、misses、invalid、timeout、errors、bypassed、used、status、hitRate。按素材准备尝试去重；同图重试是新尝试，不是独立图片数量。未观察到查缓存时 hitRate=null，不能算未命中。仅指应用持久图片缓存，不代表微信内部HTTP缓存或页面内存复用。
- `listCacheUsed` 单独表示活动列表缓存，兼容旧 `cacheUsed`；命中必须经过本地图片校验，读取/校验等待1.5秒超时和读取异常也计入摘要，不逐次发网络日志。
- 保留既有1200ms合并窗口、每批最多8条、单个日志请求在途、确认后删除及失败退避。没有改后端批量协议。正常摘要和抽样成功日志不再重复打印console/微信实时日志，仅通过后端批量队列投递。
- 普通成功日志本地写盘合并为200ms一次；错误立即落盘，并带上此前尚未落盘的普通日志。发请求前和App隐藏时落盘。进程在200ms窗口内被直接杀死可能丢少量普通成功日志，不影响图片缓存或业务。
- 不增加逐缓存查询网络请求；图片写满、过期、LRU淘汰的原因仍未细分。摘要累计统计不能跨快照简单相加。

## 可关联证据

- `home_presentation_snapshot`：页面 trace、业务列表阶段、Tab、卡片准备状态、原生回调状态、布局测量；8/15/60 秒检查点，120 秒起每分钟继续记录未完成状态。网络切换、隐藏另有记录。
- `home_media_attempt`：每个 URL 的每次 attempt 分别保存阶段；失败、成功、软/硬超时、重试排队、重试耗尽、手动重试、离页取消各自发出事件。同一毫秒不同事件通过 sequence 区分，避免上传去重误删。
- `evidence.profile`：仅保留 SDK 实际返回的排队、DNS、连接、TLS、请求/响应时间、字节数、协议和连接复用等白名单字段。`profileAvailable=false` 表示未返回，不能把缺失或平台默认零值当成耗时为零。
- `evidence.requestId`：每次 downloadFile 新建随机 ID，通过 X-Request-Id 发送。`serverRequestId`/`requestIdEchoed` 记录响应头是否对应。
- 后端 `image_transfer`：原图静态路由和 glass-image 路由都记录相同 request_id、HTTP 状态、送入 ASGI 的字节数、首 body 时间、body 是否结束和总耗时。可以与客户端 trace → attempt → requestId 对应。
- `logicalActive` 是调度占用槽数，`outstandingPreparations` 是尚未被逻辑结束的准备任务；`downloadTasksAwaitingCallback` / `inspectionTasksAwaitingCallback` 是本次小程序进程中首页调用尚未回调的 API 数。**它们不是系统 TCP 连接数**；取消后仍未回调的原生 API 仍计入，不能据此声称正在传输。

## 日志投递与保护

- 登录后沿用鉴权批量接口；未登录仅允许两个首页诊断事件走独立匿名接口。登录前生成的日志即使登录后投递也仍为匿名，不归入新账号。
- 匿名入口：单请求读取上限 128 KiB、每批最多 8 个事件、每事件 payload 最多 32 KiB、每进程每分钟最多 60 个请求。该限制是进程级而非整个集群限额。
- 队列先落盘，收到 stored=true 才删除，离线/重启重放保留事件 ID。最多 64 条、256 KiB、24 小时；投递携带 dropped、uploadFailures、storageFailures 和 queued，前三项在存储可用时保留到重启后。
- 客户端和服务端均脱敏 token、Authorization、cookie、密码及 URL query；profile 不采集 IP。
- 新结构通过 logger → 本地存储 → 重启 → FastAPI → application.log 的集成测试校验，避免深层字段变成字符串。

## 不可观测边界（不能承诺百分之百）

- getImageInfo 远程兜底的内部网络排队/连接细节不可见，也不能传入同一个自定义请求头；明确标记 `remote_network_unobservable`。
- API 回调/准备完成/setData/节点几何不证明屏幕像素已经绘制；渲染器不回调时可记录缺口，无法读取其内部执行栈。
- ASGI body 结束仅表示后端已向服务器下游交付，不证明 Caddy/CDN、运营商、用户设备都已完整接收。
- 现有 Caddy 脱敏日志继续保持原配置；没有假称其已有逐请求关联。后续网关/CDN 观测可以独立在服务端补充，不需要为关联 ID 再修改前端。
- 系统强杀、存储失败、24 小时过期/队列挤出、SDK 未回调无法保证全部事件最终到达。drop 等计数只能在后续成功上传时看到。
- 网络慢的底层责任仍需用新版真实异常会话确认；这些改动不把“Android 有问题”或“并发 3 能根治”当结论。
